# Recovery

State version 2 stores the lifecycle and recovery data required to resume a Change, including refresh checkpoints and the persisted merge subject. Version 1 manifests remain readable and are migrated in memory; the next mutation writes version 2. The `vcm.yml` schema remains version 1; these are separate contracts.

Start with `vcm status <change>`. Keep the selected repository set and Change paths intact while repairing an interrupted operation. Lifecycle state under the workspace Git common directory records only selected repository names, ownership, bases, hook outcomes, merge checkpoints, backups, and cleanup progress. VCM derives the Change identity and paths from the state filename and resolves repository paths, trunks, URLs, hooks, runners, dependencies, and ordering from the current `vcm.yml`. These local files are operational state, not project artifacts; do not execute them or edit them to bypass ownership checks.

Repositories added to `vcm.yml` after a Change was created are not part of that Change and are skipped by status, merge, and drop. If a selected repository is removed or renamed in configuration, status reports it and create recovery, merge, and drop stop. Restore that repository's configuration entry before retrying. Other current configuration changes take effect immediately, so inspect hook, runner, path, remote, trunk, and dependency changes before resuming an operation.

VCM serializes mutations with an operating-system workspace lock. If another invocation is active, let it finish. The lock is released when its process exits; the lock file may remain and should not be deleted to bypass an active lock.

For a failed hook, inspect stderr and the relevant Change checkout. Repair and commit intended output, ensure the checkout is clean, and retry the same command. Completed hooks remain skipped on retry; failed hooks run again unless their merge phase is deliberately omitted with `--skip-hooks`. An interrupted hook remains recorded as `running`: after inspecting its effects and confirming an idempotent retry is safe, change only that hook outcome's `status` to `failed` in the recorded manifest, preserving file permissions, then retry. Do not change ownership or revision fields. VCM does not promise exactly-once external effects.

Merge overrides are recovery decisions, not relaxed integrity checks. `--force` ignores only a clean lifecycle hook command's nonzero exit, records the failed outcome, and continues; it does not authorize cleanup or create a backup. Successful merge cleanup always removes Git-ignored content from owned Change worktrees after local integration is checkpointed, without requiring a VCM force flag. `--skip-hooks merge-before` or `merge-after` bypasses the configured phase for that invocation without recording completion, and `--skip-git-hooks` suppresses repository Git hooks only for Git commands launched inside lifecycle hooks. Dry-run output reports all three choices and whether ignored content will be deleted. Configuration, state, hook output, tracked or staged modifications, ordinary nonignored untracked content, ownership, revision drift, foreign nested Git repositories, conflict, and incomplete create, refresh, merge, or drop failures still stop recovery. Preserve and inspect the workspace before retrying.

Hook outcome keys use the six current phases. State containing an obsolete phase name is rejected and is not silently reinterpreted. For an inspected legacy record, `create` ran in the Change worktree and corresponds structurally to `create-after`; root `pre-merge` and child `merge` ran in the Change worktree and correspond to `merge-before`; and `drop` ran before removal and corresponds to `drop-before`. Preserve the manifest and affected Git state and verify every recorded outcome and external effect before deliberately rewriting those keys. Legacy root `post-merge` ran in the Change worktree before root integration and has no behaviorally safe mapping to the new base-repository, post-cleanup `merge-after`; complete that recovery with the legacy binary when possible, or perform an explicit inspected migration that accounts for its Git and external effects.

For an interrupted merge, inspect both the Change source and origin trunk. Completed downstream merges remain in place if a later hook or workspace merge fails. Retry the same Change after repairing the reported problem; do not reset completed targets or advance source branches behind the manager's recorded checkpoints. Unexpected source or target revisions require explicit investigation.

If a canonical local trunk advances, merge refuses to start and directs you to `vcm refresh`. Refresh never fetches. It checkpoints each selected repository, merges advanced local trunks in dependency order, preserves conflicts for repair, and resumes idempotently. If the canonical trunk advances again while a refresh is being repaired, resolve and commit the recorded conflict in the Change checkout without moving the canonical trunk backward. On retry, VCM recognizes a completed resolution commit, a recorded prepared merge commit, or a prepared index that matches the recorded merge tree; it finalizes that checkpoint and continues against the newer descendant canonical target in the same invocation. `vcm status` shows the recorded refresh target, current canonical target, and recognized recovery state.

Refresh still stops when completion cannot be proved: an unresolved merge, an unexpected Change revision that does not contain the recorded target, unrelated dirty worktree content, or a rewritten/non-descendant canonical target requires inspection and explicit repair. The error reports the recorded and current revisions when available; do not reset a safely advanced canonical trunk merely to match the old checkpoint. Run `vcm sync` to update cached remote state and `vcm pull` to update canonical local trunks before refresh when remote synchronization is intended.

After integration, merge records `merge-finalizing` separately from completed repository removal. If cleanup is interrupted, retrying plain `vcm merge <Change Tag>` removes only resources whose removal is not checkpointed, including ignored content in retained owned worktrees; no `--force` flag or recovery backup is involved. If a `merge-after` hook fails after every worktree is gone, retry from a base repository; completed removals and hook outcomes are preserved, integration is not repeated, and only pending post-cleanup hooks run. Failed `drop-after` hooks are likewise resumed with `vcm drop <Change Tag>` from a base repository after the corresponding worktree has disappeared.

`vcm sync` changes only cached remote-tracking refs. `vcm pull` rejects dirty, non-trunk, or interrupted canonical checkouts before any rebase and blocks rebases that would rewrite an active Change baseline. If pull reports a rebase conflict, Git's interrupted rebase is intentionally preserved; resolve it with Git and continue, or abort it, before retrying VCM. `drop --force` can discard working content; inspect its dry-run output and the affected resources first. Recovery backups preserve Git history and discarded filesystem content before destructive work. Keep these backups until the result is verified. A backup is recovery evidence, not authorization to overwrite unrelated work.

Pending creation-synchronization journals are stored as `vcm/*.sync` under the workspace Git common directory. After an interrupted nontrivial create-time rebase, the current revision can differ from both the recorded starting revision and remote target even if the rebase completed. VCM rejects this ambiguous outcome rather than accepting it automatically. Inspect the journal and Git history, preserve any completed rebased history with a recovery branch or tag, then explicitly repair the checkout to the reported recorded starting revision or target before retrying. Resolve unfinished Git operations and preserve working content before any reset.

Workspace publication is intentionally non-atomic across repositories. `vcm push` completes a workspace-wide preflight before publication, then pushes child trunks in dependency order and the root trunk last. A remote update race, server rejection, or transport failure can occur after earlier children have been published. Inspect the reported repository, resolve the remote failure without rewriting already-published history, and rerun `vcm push`; repositories whose remote trunk already matches the local trunk are idempotent.

Ordinary drop also rejects ignored filesystem content. Forced drop preserves discarded content in recovery backups, but still rejects foreign nested Git repositories; relocate those repositories explicitly before retrying.

Use `vcm check` to inventory dirty registered worktrees, unfinished Git operations, and local branches or worktrees that are not authorized by the configured trunks and live VCM state. Remote-tracking and recovery refs are not pruning targets. Missing resources and ownership mismatches require manual investigation; VCM protects live-state branches and paths when their registration disagrees with current configuration.

Use `vcm prune --dry-run` to review cleanup candidates. If any state file cannot be validated, pruning remains incomplete and produces no actions because that state may authorize resources that VCM cannot safely identify. A real prune requests approval for every reset, worktree removal, and branch deletion. Retained checkout resets discard tracked and ordinary untracked content at the current `HEAD` but preserve ignored files. Unexpected worktree removal deletes the entire worktree, including ignored files. Branches are deleted only after worktree processing and only if their object ID still matches the audited value. Prune creates no recovery archive or recovery ref: each confirmation is authorization for irreversible deletion, so preserve anything needed before answering yes.

VCM only removes resources it recorded as owned. If paths, branches, or worktrees were replaced manually, restore the expected ownership or resolve the discrepancy explicitly. Never delete an unfamiliar path merely because its name resembles a Change.
